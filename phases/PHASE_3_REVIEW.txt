1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
Phase 3 establishes the operational management and reporting layer for SupportFlow with
strict, dedicated role segregation across all three staff tiers:

1. Agent Dashboard (/agent/dashboard):
   - Scope: Individual contributor queue and ticket triage.
   - Access: Strictly reserved for users with role 'agent'.
   - Capabilities: Personal open/in-progress tickets, urgent/overdue triage, filterable inbox with pagination, personal activity history, and notifications placeholder.

2. Team Lead Portal (/lead/dashboard):
   - Scope: Dedicated team leadership, queue triage, and workload distribution.
   - Access: Strictly reserved for users with role 'lead'.
   - Capabilities: Team workload analytics, live agent capacity comparison, unassigned & overdue ticket queues, instant reassignment controls, and domain reporting (status, priority, category). Team leads do not need an agent dashboard.

3. Workspace Administrator Portal (/admin/dashboard):
   - Scope: Workspace governance, team member provisioning, global queue management, settings, and audit logs.
   - Access: Strictly reserved for users with role 'admin'.
   - Capabilities: Workspace overview, ticket counts by status and priority, complete staff roster management (add user, change role, toggle active status), global assignment/reassignment queue, workspace settings configuration, and paginated immutable audit ledger.

All dashboard statistics, workload metrics, and audit logs are driven by real backend
data computed via MongoDB queries and Express controllers (zero hardcoded mock stats).
Strict backend RBAC authorization ensures that frontend visibility guards are always backed
by HTTP 403 Forbidden enforcement on the API server.

All Phase 3 requirements have been built and verified with:
- 32/32 passing automated integration tests (Vitest).
- 100% clean TypeScript compilation (0 errors across backend and frontend).
- Optimized production bundles built via Vite.

3. DATA FLOWS & ARCHITECTURE
--------------------------------------------------------------------------------

A. Agent Dashboard Flow:
   1. Frontend (`/agent/dashboard`): Dispatches TanStack Query `['agentSummary']` to `GET /api/reports/agent-summary`.
   2. Express Auth Middleware: Authenticates JWT token and verifies `role === 'agent'`.
   3. Service Layer (`getAgentDashboardSummary`):
      - Calculates real-time counts for tickets assigned to `req.user._id` (`open`, `in_progress`, `highPriority`, `overdue`).
      - Identifies overdue items based on SLA thresholds (P1 > 4h, P2 > 24h, P3 > 48h, P4 > 72h).
      - Retrieves the agent's recent activity stream from `AuditEvent`.
   4. UI View: Displays real StatCards, Notifications Placeholder banner, "My Active Tickets" tab, "Urgent & Overdue Work" tab, and "Full Ticket Inbox" tab with server-side filters and pagination.

B. Team Lead Dashboard Flow:
   1. Frontend (`/lead/dashboard`): Guarded by `<RoleRoute allowedRoles={['lead']}>`. Dispatches query `['teamLeadReport']` to `GET /api/reports/team`.
   2. Express RBAC Guard (`requireRole(['lead'])`): If an Agent or Admin requests this endpoint, Express immediately responds with HTTP 403 Forbidden.
   3. Service Layer (`getTeamLeadReport`):
      - Computes team workload: total tickets, open, in progress, pending, resolved, closed, unassigned count, and overdue count.
      - Iterates active workspace users and aggregates each agent's workload distribution.
      - Gathers unassigned and overdue tickets for operational triage.
      - Computes breakdowns by status, priority, and category.
   4. Reassignment Workflow (`ReassignDropdown`):
      - Changing the assignee triggers `PATCH /api/tickets/:id/assign`.
      - Updates MongoDB `assignedTo`, records `ticket_assigned` in `AuditEvent`, and invalidates queries to synchronize all views immediately.

C. Workspace Administrator Dashboard Flow:
   1. Frontend (`/admin/dashboard`): Guarded by `<RoleRoute allowedRoles={['admin']}>`. Dispatches queries for overview, users, settings, and audit ledger.
   2. Express RBAC Guard: Endpoints `POST /api/users`, `PATCH /api/users/:id`, `PATCH /api/workspaces/current/settings`, `GET /api/reports/admin`, and `GET /api/audit` strictly enforce `requireRole(['admin'])`.
   3. Workspace Settings Form:
      - Admin modifies Workspace Name, Default Priority, or Customer Reopen toggle.
      - Calls `PATCH /api/workspaces/current/settings`. Updates MongoDB document and logs `workspace_settings_updated` audit event.
   4. Team Member Management:
      - Admin lists roster, changes roles (Agent, Lead, Admin), and toggles active access.
      - "Add Team Member" modal invokes `POST /api/users` with bcrypt password hashing and email uniqueness validation.
      - Safety guard: Prevents admin from deactivating themselves or demoting the last active administrator.
   5. Immutable Audit Ledger:
      - Tabulated view of all tenant mutations, actors, actions, and previous/new state payloads with pagination.
